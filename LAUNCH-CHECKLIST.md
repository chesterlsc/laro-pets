# Laro Pets — production-readiness checklist

## 1. Blockers before taking real orders

- **Set a durable, readable order store before enabling any payment method.** `lib/orders.ts:78-85` silently falls back to a write-only Sheets store (`get()` reads an in-process Map, `:34,:55`) or an ephemeral `/tmp` file on Vercel (`:63`) with only a `console.warn`. Orders can then 404 on `/thank-you/[orderId]` (`page.tsx:16-17`) and the PayMongo webhook 404s (`app/api/webhooks/paymongo/route.ts:29-30`), so paid orders never flip to `paid` and no emails go out. Run `supabase/schema.sql`, set `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY` in Vercel Production, and place one test COD order on the deployed URL and check the row.
- **Gate online checkout on Supabase in code.** `app/api/checkout/paymongo/route.ts:9` only checks `PAYMONGO_SECRET_KEY`; add a 503 unless both Supabase vars are set. Make `getStore()` throw (not warn) when `process.env.VERCEL` is set and no backend is configured (`lib/orders.ts:83`). Fix README.md:64 (Sheet backend does not receive status updates) and treat the Sheet webhook as COD-only.
- **Fill `content/placeholders.ts:4-16`.** Every value still renders bracketed in production: footer legal line and dead `mailto:[hello@laropets.ph]` (`content/copy.ts:142-148`), Terms/Privacy contact (`content/policies.ts:57,65`), announcement bar/shipping band/FAQ/specs/in-the-box (`copy.ts:6,89,115,121,131,133`), thank-you step 3 (`page.tsx:57`) and the customer email (`lib/email.ts:47`). `scripts/check-placeholders.mjs:2` warns and never fails; `PlaceholderBanner` is dev-only. RA 11967 seller disclosure requires the real name, address, registration and contact.
- **Decide the 30-day guarantee and 6-month warranty.** They are labelled `[Proposed policy]` in `content/policies.ts:7,13` and `copy.ts:103,106` but asserted unlabelled in the hero trust grid (`copy.ts:31`), FAQ (`copy.ts:129`), footer links (`copy.ts:142`), Returns page title (`policies.ts:39`) and Product JSON-LD `hasMerchantReturnPolicy` (`lib/seo.ts:47-54`, 30 days, FreeReturn). Either delete the labels or strip every mention including the JSON-LD block; do not ship a labelled proposal next to unlabelled promises.
- **Hide sample reviews and placeholder star rows.** `content/reviews.ts:6` is `sample: true` with invented Filipino names; `components/sections/Reviews.tsx:22` and `Hero.tsx:39,49` render five filled stars (default `count=5`) beside `[4.8 · 000 reviews]`. Gate both hero rating rows and the Reviews section (or show "Reviews coming soon") on `!reviews.sample`; only JSON-LD is gated today (`lib/seo.ts:57`).
- **Pick a supplier and test a sample before selling.** Specs in `copy.ts:112-118`, "whisper-quiet" (`copy.ts:43`), battery/playtime/feather count placeholders and `InStock` in `lib/seo.ts:39` are unverified; `research/pricing.md:12-25` lists 8 unselected listings. Run one unit of each print (`content/product.ts:8,15`) with a real cat for a week, then fill `placeholders.ts:8-10` and correct copy.

## 2. Configure before launch (owner supplies keys/facts)

- **`NEXT_PUBLIC_SITE_URL`** must be the https domain in Vercel Production + Preview. It defaults to `http://localhost:3000` in `lib/seo.ts:8`, `app/robots.ts:3`, `app/sitemap.ts:4`, `lib/paymongo.ts:5` (success/cancel URLs `:15-16`) and `lib/email.ts:7`; nothing fails the build if unset.
- **Resend:** verify the sending domain (`lib/email.ts:12` sends from `orders@<host>`), set `RESEND_API_KEY` and `STORE_OWNER_EMAIL`; without them `lib/email.ts:54` only logs. Send failures are swallowed (`:61-62`), so confirm one test order arrives. The Supabase `orders` table (index at `supabase/schema.sql:19`) is the source of truth, not the inbox.
- **PayMongo (only if launching online payments):** complete business activation/KYB, enable GCash/Maya/card on the account (otherwise session creation fails with the generic 502 at `checkout/paymongo/route.ts:20`), set `PAYMONGO_SECRET_KEY` + the matching-mode `PAYMONGO_WEBHOOK_SECRET` (`lib/paymongo.ts:33-41` holds one secret), register the live webhook for `checkout_session.payment.paid` only, keep production Deployment Protection off, and complete the unchecked README.md:238 DoD (test-mode session to `paid`). If not activating yet, remove "GCash, Maya, Visa, Mastercard" from `copy.ts:84` / `policies.ts:18` and the "Secured by PayMongo" line (`DeliveryForm.tsx:103`).
- **Vercel WAF rate limit on `POST /api/orders` and `/api/checkout/paymongo`** (e.g. 5/min per IP). Neither route has any limit, honeypot or CAPTCHA (`app/api/orders/route.ts:8-19`); each COD request writes a row and sends up to two emails (`lib/email.ts:59-60`).
- **Analytics IDs:** create GA4, Meta Pixel (verify domain in Business Manager), TikTok Pixel; set the three `NEXT_PUBLIC_*` vars (`components/Analytics.tsx:5-7`, build-time inlined) and redeploy. Verify the domain in Search Console via DNS TXT and submit `/sitemap.xml`. Smoke-test with GA4 DebugView on a COD order.
- **Contact channels:** create the Facebook Page/Messenger, Viber business account and hello@ mailbox promised at `copy.ts:127` and `policies.ts:34,42`, and set a same-day reply SLA.

## 3. Business / supplier tasks outside the code

- **Unit economics.** `content/product.ts:6-7` fixes ₱799/₱899/₱1,679, ₱79 shipping free at ₱899, and the default tier is `bundle` (`product.ts:32`), so the default order ships free. `research/pricing.md:27-46` shows ₱799 only clears 2.5x on bulk sourcing (₱312 landed) and not on single-unit (₱577). Build a per-tier margin sheet with real J&T/Flash/LBC rates by zone, COD fee, PayMongo fee, free guarantee-return shipping (`policies.ts:42`), packaging, warranty reserve, and duty + 12% VAT above the ₱10k de minimis (`pricing.md:50`). Any price change is one edit in `product.ts:6-7` plus `lib/pricing.test.ts`.
- **Fulfilment model.** Copy assumes Manila stock: "We pack your order today" (`lib/email.ts:45`, `page.tsx:57`), "packed the same day" (`policies.ts:31`), "Ships from Metro Manila" (`copy.ts:6,139`). If shipping cross-border, rewrite these to "we dispatch within N working days" and set delivery placeholders to door-to-door totals.
- **Courier accounts and daily loop.** Open merchant COD accounts (ask for COD fee, remittance cycle, RTS charge, Li-ion acceptance), set pickup, and define the manual loop: read new rows in Supabase → confirm COD by call/text → book waybill → set `status` to `fulfilled` in the Table Editor and note the waybill in `notes` (no in-app write path exists; `lib/orders.ts:116` is the only status mutation). Fulfil only `paid` and `pending_cod`; treat `pending_payment` older than ~1 hour as abandoned.
- **SMS promises.** Site promises store-sent texts at `page.tsx:30`, `policies.ts:33,54,66`, `copy.ts:89`, `email.ts:47`; SPEC.md:28 excludes SMS and no provider exists. Either commit to texting manually from a business SIM (and "confirm COD before dispatch") or reword to attribute tracking texts to the courier and drop "confirmed by SMS".
- **Refund SOP.** `policies.ts:42,67` promise refunds; no code path exists. Document: PayMongo dashboard → Payments → Refund for online, GCash/bank transfer for COD, then set `status='cancelled'` and note the refund id in `payment_ref` in Supabase.
- **Registration and privacy notice.** Register DTI (or SEC — label is hard-coded "DTI" at `copy.ts:143`, `policies.ts:65`) and BIR; set up BIR-registered invoices (booklet or e-invoicing). In `policies.ts:57` name a DPO/privacy contact, state 10-year retention (BIR RR 17-2013), and list actual processors (Vercel, Supabase + region, Resend, PayMongo).
- **Stock and refills.** Track stock per print in a Sheet; on sellout remove the print from `product.ts:8` (checkout enum derives from it, `lib/order-schema.ts:19`). Hold physical 3-feather packs compatible with the hub (`product.ts:6,11-12`) and a few spare hubs for warranty swaps. Supply the "Quick-start guide" promised at `copy.ts:121` (one card, can carry the safety line from `policies.ts:69`) or bracket it.
- **Asset rights.** Demo video and the ten product images (`content/images.ts:3-12`, copied from `_src/laro-mockup-a-package`) have no recorded licence; get supplier permission in writing or reshoot once samples arrive, then update `product.ts:23` uploadDate. Get written creator permission before filling `content/ugc.ts`.
- **Wording fixes:** soften the hard 48-hour photo deadline at `policies.ts:44`; make the COD confirmation email (`email.ts:45-47`) say "We'll text you to confirm before we pack" instead of "We pack your order today".

## 5. Fine as-is

- Webhook signature verification (HMAC-SHA256 over `${t}.${rawBody}`, `timingSafeEqual`, unit-tested in `lib/commerce.test.ts`).
- Secrets: service-role/PayMongo/Resend keys read only server-side; `.env*` gitignored; prices recomputed server-side (`lib/orders.ts:96`, `lib/paymongo.ts:12`); centavo math, PHP currency and `gcash`/`paymaya`/`card` ids correct.
- Thank-you page keyed by an unguessable UUID, `noindex` — same pattern as Shopify order-status pages.
- Pixels without a consent banner: disclosed in `policies.ts:56`, common PH practice, not a launch blocker.
- "Prices include VAT where applicable" wording (`policies.ts:66`) works for VAT and non-VAT registrants.
- No admin UI, no CSV export, manual status edits in Supabase, meta title/description length: acceptable at launch volume.
- Orphan `pending_payment` rows from abandoned checkouts: distinguishable by status, trigger no emails.
